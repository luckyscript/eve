# Verifiable skill evolution

The user request is the acceptance specification. Implementation stays in the existing main checkout, with one writer, native Node ESM and no dependencies. No agents, global configuration changes, credential output, force pushes, or changes to prior research documents.

Registry objects live under ignored `.eve/evolution`, directories 0700, files 0600. Skill bytes are SHA-256 addressed and immutable. One cross-process publication lock protects atomic state replacement and compare-and-swap publication. Candidate metadata includes parent, source session/run/contract hash, model configuration hash, evaluation references and lineage query accounting. Baseline import is an explicit trusted user operation. Published snapshots override same-name trusted filesystem skills; other manual skills remain compatible. Ordinary tools cannot access `.eve`, modify configured skill roots, or create SKILL.md. Loaded published bytes are fixed for the run.

A JSON suite version 1 contains cases with prompt, string-valued input files and existing declarative contracts. Extend contracts with exact text and SHA-256 assertions. Freeze suite bytes before generation. Generator receives only source task, public failure category, user correction and old skill, via a single independent request without tools. It never receives contracts, hidden cases, case logs or suite paths. Host runs baseline/candidate in separate workspaces below `.eve/evolution`, copies only their skill and declared inputs, and retains private run ledgers. Same model and explicit bounded steps, output tokens, tool calls and timeout for both arms. Evaluation requires actual load_skill trace, model completion and all independent contracts. Promotion requires every candidate case pass and at least one baseline failure, thereby preserving every baseline success. Uncertainty fails closed. Evidence is local, small-sample, not a claim of general improvement.

CLI supports capabilities, evolve import --file FILE, evolve --session ID --run ID --skill NAME --suite FILE --correction TEXT --max-requests N, evolve promote ID, evolve rollback NAME, and run --auto-evolve with matching explicit skill/suite/request budget. Auto evolution attempts one candidate after acceptance failure and never replays the original task. A lineage has a persisted finite candidate limit; evaluations are not repeatedly queried on a frozen candidate. The request ceiling reserves worst-case calls before spending. Wall time is also bounded.

One feature commit includes registry, runner, CLI, tests, docs and live demonstration. Targeted tests precede commit/push; full tests/check/TUI and live compatibility follow push. Real verification must demonstrate failed source, real generated candidate, four hidden cases, publication, fresh-process loading, rollback and rejected promotion with unchanged active state. Reports remain ignored and contain hashes, tool traces and contract results rather than self-report alone.
